# AV Numbers — 数理設計（コンセプト仕様）

すべての数が「小さい / 普通 / 大きい」の3状態を持ち、その状態が足し算・引き算の中で相殺・増幅・反転する計算ゲームの、数理的な仕様をまとめる。

ゲーム全体のステージ構成・UI仕様は [GAME_DESIGN.md](./GAME_DESIGN.md) を参照。

## 0. 着想の背景

このゲームの発想の原点は、5歳児が示した次のような素朴な感覚にある（表現はあくまで着想段階のものであり、以下で定義する正式な数理仕様とは厳密には一致しない）。

- 「大きい1 ＋ 1 ＝ 大きい2」
- 「小さい1 ＋ 小さい1 ＝ 小さい2」
- 「大きい1 ＋ 小さい1 ＝ 2」

数字そのものに「大きい・小さい」という状態がくっついていて、足し算をするとその状態が一緒に運ばれたり、逆向きの状態同士だと打ち消し合って「普通」に戻ったりする——という直感である。

この直感を、`v`（小さい）・無印（普通）・`A`（大きい）という3状態と、`nv = n - 1/3` / `nA = n + 1/3` という数直線上の位置として厳密に定式化したものが、以下の仕様である。子どもの直感通りに動く場面（例：`1A + 1 = 2A`、`1A + 1v = 2`）もあれば、2段分の状態が重なって整数部が繰り上がる「正規化」（例：`1v + 1v = 1A`）のように、直感をそのまま拡張すると素朴には出てこない振る舞いも仕様として整合的に定義している。この「素朴な直感と、厳密な規則との差」自体が、このゲームで遊びながら発見してほしい面白さの中心になっている。

## 1. 基本コンセプト

このゲームでは、**数字だけ**が3つの状態を持つ。

| 記号 | 意味 |
| --- | --- |
| `v` | 小さい |
| 無印 | 普通 |
| `A` | 大きい |

タイトルの「AV」を、そのままゲーム内の状態記号として使う。ゲーム内では小さい側だけ小文字の `v` とし、見た目でも大小が分かるようにする。

演算子は通常の `+ / -` のみを使用し、**演算子に `v / A` は付けない**。

重要なのは、左右の数字が持つ状態が、足し算ではそのまま合成され、引き算では右側の作用方向が反転すること。

## 2. 数字の定義

各整数 `n` には3種類の数がある。

- `nv = n - 1/3`
- `n = n`
- `nA = n + 1/3`

つまり、`v` はその整数から **1/3下**、`A` はその整数から **1/3上**を表す。

例えば、1から2の間は次の順番になる。

```text
1 → 1A → 2v → 2
```

したがって、

```text
1A = 1 + 1/3
2v = 1 + 2/3
```

数全体の並びは次のようになる。

```text
… < 1A < 2v < 2 < 2A < 3v < 3 < 3A < 4v < 4 < …
```

`2A` と `3v` は別の数である。

## 3. 演算子

初期版では通常の足し算 `+` と引き算 `-` のみを扱う。演算子自体には状態を持たせない。

### 足し算

左右の数をそのまま足す。数字の `v / A` の作用も同方向に合成される。

### 引き算

右側の数を引く。右側の数字に付いた `v / A` は、引かれることで作用方向が反転する。

- 小さい数を引く → 結果は1段上がる
- 大きい数を引く → 結果は1段下がる

## 4. 「1段」の意味

この世界では **1段 = 1/3**。

例えば `2` の周辺は、

```text
1A → 2v → 2 → 2A → 3v
```

となる。したがって、

- `2` から1段上 = `2A`
- `2` から2段上 = `3v`
- `2` から1段下 = `2v`
- `2` から2段下 = `1A`

## 5. 数字側の v / A の作用

数字についている `v / A` は、その数字自体の位置を1段ずらす。

```text
5v = 5より1段下
5A = 5より1段上
3v = 3より1段下
3A = 3より1段上
```

足し算では左右の作用をそのまま合成する。引き算では右辺の大小の効果が反転する。

- 左側の `v` → 結果を1段下げる
- 左側の `A` → 結果を1段上げる
- 右側の `v` を引く → 結果を1段上げる
- 右側の `A` を引く → 結果を1段下げる

## 6. 基本計算例

```text
1v + 1A = 2
1v + 1v = 1A
4v + 3v = 6A
2A + 3A = 6v
5 - 3    = 2
5 - 3v   = 2A
5 - 3A   = 2v
5A - 3v  = 3v
5v - 3A  = 1A
```

## 7. 左右両方に v / A が付く場合

基準となる整数計算から、それぞれの数字状態の作用を合成する。引き算の場合の作用は次の通り。

| 場所 | v | 無印 | A |
| --- | --- | --- | --- |
| 左の数字 | -1段 | 0 | +1段 |
| 右の数字 | +1段 | 0 | -1段 |

例：

```text
5A - 3v
基準：5 - 3 = 2
左辺 5A：+1段
右辺 3v：+1段
合計     ：+2段
答え     ：3v
```

その他：

```text
5v - 3v = 2
5A - 3A = 2
5v - 3A = 1A
5A - 3v = 3v
```

## 8. 一般ルール

状態を数値化すると計算しやすい。

```text
v = -1
無印 = 0
A = +1
```

### 足し算

左の数字の状態 + 右の数字の状態を合成する。

### 引き算

左の数字の状態 - 右の数字の状態を合成する。

状態の合計が `-1 / 0 / +1` を超える場合は、隣の整数へ繰り上げ・繰り下げて正規化する。

```text
+2段 = 次の整数の v
-2段 = 前の整数の A
```

数字2個の二項演算では、状態作用の合計は原則 `-2〜+2段` の範囲になる。

## 9. 設計上の狙い

このゲームの中心は、**数字が持つ3状態と、演算による状態作用の合成**にある。代表的な現象は次の通り。

- **移動**：片側だけに `v / A` が付き、答えが1段動く
- **相殺**：逆向きの作用が打ち消し合う
- **増幅**：同方向の作用が重なる
- **正規化**：2段移動した結果、整数部と状態表記が切り替わる
- **反転**：引き算では右側の状態作用が反転する

演算子に状態を持たせる案は、数字側の状態と数学的に独立した意味を持たせられず、数字の状態へ還元できてしまうため採用しない。

> **正式採用ルール**
> `1A` と `2v` は別の数として扱う。
> `v / A` が付くのは数字のみ。演算子は通常の `+ / -` とする。
> これにより、「すべての数が3状態を持つ」という単一の構造原理に絞る。

## 10. UI / UX方針

- 通常プレイでは `A = 右へ1つ / v = 左へ1つ` を中心に理解させる
- `?` ボタンからルールへ1タップでアクセスできるようにする
- 詳細ルールでは `v = n - 1/3`、`A = n + 1/3` と数直線を見せる
- 初回は短い操作型チュートリアルで理解させる
- 不正解時は、基準となる整数計算から各数字状態が何段作用したかを数直線アニメーションで見せる
- 正解時のフィードバックはスクロール位置に依存せず画面内に固定表示し、確認できてから次問へ進む

## 11. 実装時の方針

最初は `+ / -` のみ実装する。

1. 数字を「整数部 + 状態（`v / 無印 / A`）」として扱う
2. 演算子は通常の `+ / -` のみとし、状態を持たせない
3. 足し算は左右の状態を加算、引き算は右状態の符号を反転して合成する
4. 演算後に `nv / n / nA` 形式へ正規化する
5. UIより先に演算エンジンのテストを作る
6. 基本・境界・複合パターンを十分にテストしてからゲーム画面を作る

> **実装メモ**
> 画面表示は `v / A` を使用する。内部コードでは可読性のため `small / normal / large` など別名で管理してもよい。
