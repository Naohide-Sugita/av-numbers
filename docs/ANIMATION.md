# AV Numbers — アニメーション強化設計

現在のプロトタイプ（[`AV_Numbers_prototype_v9.html`](../AV_Numbers_prototype_v9.html)）に既にある数直線アニメーションを土台に、アプリ全体の動きをより充実させるための設計。ゲームループやUI仕様そのものは変えず、「同じ操作・同じ画面構成のまま、手触りと理解のしやすさを上げる」ことが目的。本ドキュメントの強化項目（3節）はv9に実装済み。

## 1. 現状の棚卸し

以下は、本ドキュメントの強化項目を実装する前（v8時点）の棚卸しであり、この現状分析が強化方針の出発点になった。3節の各項目はv9で実装済み。

| 箇所 | 実装内容 | 状態 |
| --- | --- | --- |
| 不正解時の数直線 | `animRail` / `placeCursor` / `animateRail`。カーソルが `transform: translateX` で `.48s cubic-bezier(.2,.8,.2,1)` かけてスロット間を移動し、作用理由（キャプション）を1ステップずつ表示する | あり（本アプリの中核演出） |
| チュートリアルの数直線 | 上記と同じ仕組みを流用し、`← / →` 操作でカーソルが実際に動く | あり |
| 正解時のフィードバック | 画面上部に固定表示されるバナー。表示・非表示はクラス切り替えのみ | 演出なし（即時表示） |
| 不正解時のシート | 画面下からのシート。表示・非表示はクラス切り替えのみ | 演出なし（即時表示） |
| 画面遷移（ホーム/ステージ一覧/ゲーム/結果） | `hidden` クラスの付け外し | 演出なし（即時切り替え） |
| 進捗バー | `width` を問題数に応じて変更 | 演出なし（即時変化） |
| キー入力（数字キー・矢印キー） | 標準のボタン押下のみ | 演出なし |
| 結果画面のスコア表示 | テキストとして即時表示 | 演出なし |

**数直線アニメーションのみがこのゲームの核（`v / A` の作用を視覚的に理解させる仕組み）として作り込まれており、それ以外の画面遷移・フィードバック・入力の手触りは未着手**、というのが現状。

## 2. 強化の設計方針

1. **意味を伝えるアニメーションを最優先する。** 装飾目的だけの演出（結果画面のconfettiなど）より、`v / A` の作用・反転・正規化の理解を助ける演出を優先する
2. **既存の数直線アニメーション基盤を拡張する。** `animRail` / `placeCursor` / `animateRail` を土台にし、別の新しいアニメーション機構を並行して作らない
3. **`transform` と `opacity` のみで動かす。** レイアウトサイズ（`width` / `height` / `top` / `left` 等）を伴うアニメーションはGPU負荷が高く、[GAME_DESIGN.md 4節](./GAME_DESIGN.md#4-回答入力ui)の「スマホ1画面内で完結・縦スクロールなし」という制約とも相性が悪いため避ける。進捗バーの `width` 変化のみ例外として許容する
4. **`prefers-reduced-motion: reduce` に対応する。** モーションを減らす設定のユーザーには、移動系アニメーションを `duration: 0`（実質即時反映）にフォールバックする
5. **画面のレイアウト・情報構成は変えない。** アニメーションは既存要素の中で完結させ、新しいDOM構造やスクロールを発生させない

## 3. 強化項目

### 3.1 不正解時の数直線アニメーション（最優先）

- カーソルの移動に、方向を強調する軽いバウンス（オーバーシュート）を加える
- 移動元スロットと移動先スロットを、移動の瞬間だけ軽く発光・拡大させ、「どこからどこへ動いたか」を明確にする
- キャプション（作用の説明文）の切り替えを `opacity` のクロスフェードにする（現状は即時切り替え）
- 引き算で作用方向が反転する場面（`5 - 3v = 2A` など）では、カーソルの脇に反転を示す小さな矢印アイコンを一瞬表示する
- **Stage 3（逆算）専用の拡張**：既知項とターゲットを数直線上の2点として表示し、既知項の位置からターゲットの位置までカーソルが移動する様子をアニメーションする。移動量がそのまま `?` の答えであることが伝わるようにする（詳細な起点・向きの算出は [GAME_DESIGN.md 16.4節](./GAME_DESIGN.md#164-不正解時の解説)を参照）。新しいアニメーション機構は作らず、既存の `animRail` / `placeCursor` / `animateRail` にそのまま乗せる

#### 3.1.1 プレイヤー自身の間違った答えの可視化

- 数直線が表示された瞬間から、**プレイヤーが実際に入力した(間違った)最終位置**に、淡い色・控えめなスタイルの静的マーカーを置いておく（正解を示す主カーソルとは明確に区別できる見た目にする：例えば薄いグレーの輪郭のみ、塗りつぶしなし）
- 主カーソルは、通常通り基準位置から正解の位置まで段階的にアニメーションする。プレイヤーは常に「間違った位置（静的マーカー）」と「正解へ向かう動き（主カーソル）」を同一の数直線上で見比べられる
- 基準値自体を間違えていた場合（`baseOk` が false）も、同じ数直線上でスロット位置として扱う。基準値の違いが数直線上の開始位置のズレとして視覚化される

#### 3.1.2 タップによるステップ送り

- 数直線アニメーションの表示エリアをタップすると、自動再生のタイマーを待たずに次のステップへ即座に進める（3項以上の式で、待ち時間を感じさせないため）
- 自動再生自体は止めない。何もしなければ今まで通り自動で最後まで進行する。タップは「早送り」の役割のみを持つ
- 全ステップが表示し終わった後にタップしても何も起きない（誤操作で次の問題に進んでしまうことを防ぐため、「次へ」ボタンとは独立した操作にする）

### 3.2 正解時のフィードバック

- バナーの表示を、上から軽くスライド＋フェードインするポップインに変更する（現状は即時表示）
- チェックマークをSVGにし、`stroke-dashoffset` で描画されるアニメーションにする
- 「普通の計算」の値 → 「移動後」の値の順に、軽いタイムラグを付けて強調表示する（思考順序と演出の順序を一致させる）

### 3.3 不正解時のシート

- 下からの `transform: translateY` によるスライドインに変更する（現状は即時表示）
- シートの表示と数直線アニメーションの開始タイミングを連動させる

### 3.4 画面遷移（ホーム／ステージ一覧／ゲーム／結果）

- `hidden` の即時切り替えを、フェード＋わずかな `translateY` のクロスフェードに変更する
- ゲーム画面から結果画面への遷移は、達成感を出すために少し強め（軽いズーム＋フェード）の演出にする

### 3.5 結果画面

- 正解数を `0` から実際の値までカウントアップさせる
- `10/10 Perfect` の場合のみ、追加の演出（星やパーティクル程度の軽いアニメーション）を加える。Clear（8〜9問）とRetry（7問以下）では演出の強弱を変え、Perfectだけを特別扱いする
- パーティクル演出は**外部ライブラリを使わず、CSSアニメーションのみで完結させる**（[DEPLOYMENT.md](./DEPLOYMENT.md)の「単一HTML・外部依存なし」という方針と一致させる）。例えば、あらかじめ用意した数個の星型要素に、ランダムな方向・遅延をつけた `transform`（移動＋回転）と `opacity` のCSSアニメーションを付与する程度に留める

### 3.6 進捗バー

- 現状の即時 `width` 変化に `transition: width .3s ease-out` を加え、問題が進むごとに滑らかに伸びるようにする

### 3.7 入力のマイクロインタラクション

- 数字キー・矢印キー・OKキーの押下時に `transform: scale(.95)` 程度の縮小フィードバックを加える（`:active` 疑似クラス＋短いtransition）
- 基準値・移動後の値が両方そろい `OK` が押せる状態になった瞬間、`OK` ボタンに軽いパルスを1回入れて「押せるようになった」ことを知らせる

### 3.8 `v / A` シンボルの強調

- 問題文が表示された瞬間、`v / A` の文字部分だけ軽くポップイン（スケール＋フェード）させ、まずその記号の存在に注意を向けさせる
- チュートリアル画面1（数直線 `1 → 1A → 2v → 2` を見せる場面）でも同様の強調を行い、記号の意味づけを最初から視覚的に一致させる

### 3.9 チュートリアル画面0（コンセプト紹介）

[GAME_DESIGN.md 7節「画面0：コンセプトの紹介」](./GAME_DESIGN.md#画面0コンセプトの紹介)で定義した、チュートリアル最初の導入画面のための演出。他の画面と異なり、理解度を確認するための演出ではなく、**世界観を伝えるための雰囲気演出**として設計する。

- 子どものシルエットのイラストをまず表示し、続けて3つの例文（「大きい1 ＋ 1 ＝ 大きい2」など）を1つずつ自動でポップイン表示する
- 例文が現れるタイミングに合わせて、シルエットにも軽いモーション（例：うなずく、手を上げる程度の単純な動き）を付け、例文が「子どもが話している」ことを直感的に伝える
- 3つの例文の後、橋渡しの一文「この発想から、数字が『小さい・普通・大きい』の3つの状態を持つ、というゲームが生まれました。」を最後のビートとして表示する。この一文は子どものシルエットではなく、ゲーム側のトーンで見せる（例：シルエットをフェードアウトさせてから一文を表示するなど、視覚的に語り手が切り替わったことが分かる演出にする）
- 演出は自動再生のみとし、タップで進める操作は挟まない（3.1〜3.8とは異なり、プレイヤー操作へのフィードバックではなく、一方向のアニメーションで完結させる）
- 一連の表示（3つの例文＋橋渡しの一文）が完了した時点で「次へ」ボタンを有効化する（`disabled` 解除のトリガーとして、最後のアニメーション終了イベントを使う）
- `prefers-reduced-motion: reduce` の場合は、順番にポップインさせず3つの例文と橋渡しの一文を即座に全表示し、「次へ」も即座に有効化する

## 4. 実装の優先順位

1. **不正解時の数直線アニメーションの質向上**（3.1）— このゲームの理解に直結するため最優先
2. **正解時のポップインと `v / A` の強調**（3.2, 3.8）— 状態記号の意味を強く印象づける
3. **チュートリアル画面0のコンセプト演出**（3.9）— 初回体験の第一印象を左右するため、チュートリアル関連では優先度高め
4. **進捗バーのtransition、入力のマイクロインタラクション**（3.6, 3.7）— 全体の手触りの底上げ
5. **画面遷移のクロスフェード、結果画面の演出**（3.4, 3.5）— 仕上げ

`prefers-reduced-motion` 対応（方針4）は、優先順位に関わらず最初から組み込む前提とする。
